# GFC v1.1.1 — OTA 安装可靠性 + 固件 r16

- **级别：** Patch
- **Tag（建议）：** `v1.1.1`
- **日期：** 2026-07-19
- **固件包名（权威）：** `gfc-client 1.1.0-r16`（`PKG_VERSION=1.1.0` + `PKG_RELEASE=16`）

## 版本命名（刷机 / 制品库）

| 记号 | 本版取值 | 用途 |
|------|----------|------|
| 产品版本 | **v1.1.1** | 对外口头、矩阵 `product.current`、Git tag |
| 客户端 opkg / manifest | **1.1.0-r16** | ImmortalWrt 包版本；**≠** LuCI `~git` |
| Runtime OTA 制品 `version` 字段 | 建议 **`1.1.0-r16`** | 与 `VERSION` 文件、平台短路 ack 一致 |
| Runtime 包文件名示例 | `gfc-immortalwrt-runtime-amd64-1.1.0-r16.tar.gz` | `pack-runtime.sh` 的 `VERSION=1.1.0-r16` |
| OEM 镜像 | 构建产物 `*.img.gz`；验收以 manifest 钉 **r16** | 勿用 LuCI 哈希当固件版本 |

> 从 **r15** 起：同 Major 直升；本 Patch 可 Runtime OTA 或刷含 r16 的 OEM 图。

## 组件钉扎

| 组件 | 版本 |
|------|------|
| control_plane_api | 0.1.0（无强制升级） |
| node_agent | 0.3.1（无强制升级） |
| gfc_client | **1.1.0-r16** |
| client_proto / node_proto | 1 |

## 变更摘要

- OTA：`GFC_SAFE_INSTALL` 安装期不再中途 `pkill` api/agent，避免 SIGPIPE 半装
- 安装日志：`/var/log/gfc-client/ota-install.log`
- 成功标记：`/var/lib/gfc-client/state/ota-result.json`（重启控制面进程前落盘）
- Agent：已到目标版本 / marker 命中则短路 ack，避免重复整包

## 验收检查清单

### A. 固件构建机（刷机通道）

- [ ] 源码 `gfc-client/deploy/immortalwrt/package/Makefile`：`PKG_RELEASE:=16`
- [ ] `git pull` 后再跑 `rebuild-gfc-image.sh`（勿用旧 staging）
- [ ] 验收：`grep gfc-client $IMT_SRC/bin/targets/x86/64/*.manifest` → **`gfc-client - 1.1.0-r16`**
- [ ] 盒上：`opkg list-installed | grep gfc-client` → `1.1.0-r16`
- [ ] 功能探针：`wget -qO- http://127.0.0.1:8080/api/v1/upgrade/status` 有 JSON；`phase` 可读

### B. Runtime 制品（平台 OTA 通道）

- [ ] 构建：`VERSION=1.1.0-r16 ./deploy/immortalwrt/pack-runtime.sh`（或等价）
- [ ] 包内含 `usr/lib/gfc-client/VERSION` 内容为 `1.1.0-r16`
- [ ] 包内 `upgrade-runtime.sh` 含 `OTA safe mode` / `write_ota_result`
- [ ] 控制台上传制品：`version=1.1.0-r16`，arch 与设备一致，sha256 正确，启用

### C. 平台下发 OTA（已具备 OTA 能力的 r15+ 盒子）

- [ ] 平台对单设备下发 runtime_upgrade / 或盒内 LuCI「立即升级」
- [ ] **允许**短暂离线（dataplane 停、末尾重启 api/agent）
- [ ] 升级过程中：`logread -e upgrade` 或 `tail -f /var/log/gfc-client/ota-install.log` 持续有输出，**不应**在 `install binaries` 前无故中断
- [ ] 成功后存在：`cat /var/lib/gfc-client/state/ota-result.json` → `"status":"ok"`，`version` 为 `1.1.0-r16`
- [ ] `cat /usr/lib/gfc-client/VERSION` → `1.1.0-r16`
- [ ] Agent 重新上线；平台 `last_upgrade.status` 为成功（或二次心跳短路 ack 后成功）
- [ ] 再次下发同一版本：应短路，不重复长时间下载（日志含 `already applied` / skip）

### D. 盒内 Web OTA（LuCI 升级页）

- [ ] 「检查更新」能列出制品
- [ ] 「立即升级」HTTP 立即返回；进度轮询不因 LuCI 超时失败
- [ ] api 重启后 `/api/v1/upgrade/status` 能从磁盘 hydrate 出 `done`（或至少 VERSION 已是 r16）
- [ ] `gfc-api` / `gfc-agent` 最终为 running：`/etc/init.d/gfc-api status` 等

### E. 回归（确认未伤其他模块）

- [ ] 未改 nft / unbound / sing-box 架构生成逻辑
- [ ] 手工 SSH（无 `GFC_SAFE_INSTALL`）`./install.sh` 仍可全量停服务升级（运维场景）
- [ ] 反向 SSH：升级结束后若会话曾开，`gfc-reverse-ssh` 可恢复或 restore 标记被消费
- [ ] 控制面仅上传制品即可，**无需**发版控制面代码

### F. 失败时排障（应很少出现）

```sh
cat /var/lib/gfc-client/state/ota-result.json
tail -n 80 /var/log/gfc-client/ota-install.log
ls -l /usr/bin/gfc-api /usr/bin/gfc-agent /usr/lib/gfc-client/VERSION
/etc/init.d/gfc-api status; /etc/init.d/gfc-agent status
```

若 marker 为 `failed`：修因后重新下发同一制品即可（脚本可重复执行）。
